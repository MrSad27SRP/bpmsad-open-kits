# بستهٔ آموزشی مغایرت تراکنش

هدف این بسته ارائهٔ یک نمونهٔ عمومی با دادهٔ ساختگی برای تحلیل زمان رسیدگی، طراحی پرونده و آماده‌سازی آزمون Bizagi است.

| مرحله | تحویل |
| --- | --- |
| پژوهش | [فرض‌ها، روش، نتایج و کد بازتولید](../research/) |
| طراحی | [BPMN مسیر موازی](dispute.bpmn) و [مدل SQLite](schema.sql) |
| اعتبارسنجی | [آزمون دو پروندهٔ ساختگی](test_pilot.py) و معیارهای پذیرش زیر |

از ریشهٔ مخزن `python dispute/test_pilot.py` را اجرا کنید. مدل مسیر اصلی از دریافت تا ابلاغ و بستن است. مدل مفهومی یک زیرفرایند رویدادی غیروقفه‌ای با زمان‌سنج ۷۲ ساعته دارد. در Bizagi، پیش از ایجاد کار ارجاع باید نبود تصمیم در موعد و یکتایی ارجاع به‌صورت اتمیک بررسی شود. زمان‌سنج مدل آموزشی از شروع پرونده محاسبه می‌شود. موعد واقعی باید از سیاست و تقویم کاری استخراج شود. زمان‌های SQLite را با قالب ثابت ISO 8601 و منطقهٔ UTC وارد کنید. در این مدل آموزشی هر فعالیت حداکثر یک رخداد دارد. یکپارچه‌سازی واقعی باید تحویل ابلاغ، تلاش مجدد و بازگشایی را جدا ثبت کند.

## معیارهای پذیرش Bizagi

| سناریو | شواهد لازم در Work Portal |
| --- | --- |
| ثبت و ارسال تکراری | یک پرونده برای همان کلید ارسال، حتی با دو درخواست هم‌زمان |
| تکمیل دو شاخه | بررسی پس از تکمیل هر دو شاخه، با هر ترتیب تکمیل |
| پذیرش و رد | تصمیم، نقش و زمان پس از خروج و بازخوانی باقی بمانند |
| عبور از موعد | ارجاع یک‌بار ثبت شود و رسیدگی ادامه یابد |
| خطای ابلاغ | تلاش مجدد به ارسال تکراری به مشتری منجر نشود |
| کنترل دسترسی | نقش ثبت‌کننده نتواند تصمیم را ثبت یا تغییر دهد |

آزمون SQLite قیود یکتایی و ترتیب دو نمونه را می‌سنجد. پذیرش موارد بالا به محیط Bizagi و اجرای واقعی نیاز دارد.
